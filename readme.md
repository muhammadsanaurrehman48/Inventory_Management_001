# 📦 Inventory & Sales Management System
> Built in x86 Assembly Language using MASM 6.15 and Irvine32  
> With a Python Analytics Dashboard powered by pandas and Matplotlib

A fully functional, console-based Inventory Management System written **entirely in x86 Assembly language**. The system manages product records, tracks real-time stock levels, processes sales transactions, and persists all data in a binary file. A companion Python dashboard provides executive-level business analytics from the exported CSV.

## 🔍 Overview

This project demonstrates that real-world business software can be engineered at the lowest hardware abstraction level. Every operation — from reading user input to writing binary files — is implemented using raw x86 instructions, CPU registers, and Win32 API calls. There is no runtime, no garbage collector, and no standard library beyond Irvine32 for basic I/O.

The system is split into **seven Assembly modules** linked into a single executable, following a clean separation of concerns. A **Python script** bridges the gap between low-level data storage and high-level business insight by reading the exported CSV and rendering an analytics dashboard.

---

## ✅ Features

### Core Inventory
- Add new products with unique ID, name, quantity, and price
- View all products in a formatted, fixed-width table
- Update any product's name, quantity, or price by ID
- Delete products with confirmation prompt; all arrays shift correctly

### Sales
- Record sales by product ID and quantity
- Automatic stock deduction with insufficient-stock guard
- Cumulative units-sold counter (`itemSold`) per product, persisted across restarts
- Instant total sale value printed at point of sale (`price × quantity`)

### Data Persistence
- All data saved to `data\inventory_data.dat` as a fixed 364-byte binary file on exit
- Data automatically loaded on startup — inventory survives restarts
- Graceful first-run handling when no data file exists

### Export & Dashboard
- One-click CSV export to `data\export.csv` with five columns: ID, Name, Quantity, Price, Units Sold
- Python analytics dashboard with four business charts and a full data table

### UI
- Color-coded console interface using Irvine32's `SetTextColor`
- Cyan title, white menu options, yellow error messages, green success messages
- Fixed-width table formatting with padded columns

## 🏗️ System Architecture

The application is organized into seven Assembly modules. Inter-module communication is achieved exclusively through MASM's `PUBLIC` and `EXTERN` directives — no global state is duplicated.

| Module | Role |
|--------|------|
| `main.asm` | Entry point. Calls `LoadData` on startup, loops on `showMenu`, calls `SaveData` on exit, then calls `WaitMsg` before closing. |
| `menu.asm` | Renders the color-coded 7-option menu. Reads user choice via `ReadInt` and dispatches using a `cmp`/`je` chain. Returns `eax=1` to signal exit. |
| `inventory.asm` | Implements all CRUD operations and internal helpers: `FindByID`, `NameOffset`, `CopyName`, `ZeroName`, `PrintPadded`, `PrintDecPadded`. |
| `sales.asm` | Implements `RecordSale`. Searches for the product, validates stock, deducts from `itemQty`, accumulates into `itemSold`, and prints total via `MUL`. |
| `file.asm` | Implements `SaveData`, `LoadData`, and `ExportCSV` using raw Win32 API calls (`CreateFileA`, `WriteFile`, `ReadFile`, `CloseHandle`). Contains custom `IntToStr` and `GetStrLen` helpers. |
| `data.asm` | Single source of truth. Declares all five parallel arrays and every string message constant as `PUBLIC`. |
| `utils.asm` | Empty placeholder reserved for future shared helper procedures. |

### Program Flow

```
START
  │
  ▼
LoadData(data\inventory_data.dat)
  │  ── file exists?  YES → load 364 bytes into arrays
  │  ── file exists?  NO  → print "Starting fresh", continue
  │
  ▼
┌─────────────────────────────┐
│        showMenu()           │ ◄──────────────┐
│  1. Add Product             │                │
│  2. View Products           │                │
│  3. Record a Sale           │                │
│  4. Update Product          │                │
│  5. Delete Product          │   eax = 0      │
│  6. Export to CSV           │────────────────┘
│  7. Exit                    │
└─────────────────────────────┘
  │
  │ eax = 1 (user chose 7)
  ▼
SaveData(data\inventory_data.dat)
  │
  ▼
Print goodbye → WaitMsg → EXIT
```

## 🗄️ Data Organisation

All product data is stored in **five parallel fixed-size arrays** in `data.asm`. A single index register (`esi`) addresses the same logical record across all arrays simultaneously — this is the Assembly equivalent of a struct array.

```asm
MAX_ITEMS = 10
NAME_LEN  = 20

itemCount DWORD 0                           ; number of active records
itemIDs   DWORD MAX_ITEMS DUP(0)            ; unique product IDs
itemQty   DWORD MAX_ITEMS DUP(0)            ; current stock quantity
itemPrice DWORD MAX_ITEMS DUP(0)            ; unit price in Rs
itemSold  DWORD MAX_ITEMS DUP(0)            ; cumulative units sold
itemNames BYTE  MAX_ITEMS * NAME_LEN DUP(0) ; product names (20 bytes each)
```

Accessing record `i`:
```asm
mov eax, itemIDs[esi*4]     ; read ID of record i
mov eax, itemQty[esi*4]     ; read stock of record i
mov eax, itemPrice[esi*4]   ; read price of record i
```

## 🔨 Build & Run

### Step 1 — Assemble and Link
```bash
build.bat
```
This runs `ml /c /coff` on each `.asm` file and links all `.obj` files with `Irvine32.lib` to produce `main.exe`.

### Step 2 — Run the Application
```bash
main.exe
```

### Step 3 — Export CSV from the App
Inside the running application, select option **6. Export Data to CSV**. This writes `data\export.csv`.

### Step 4 — Launch the Dashboard
```bash
launchDashboard.bat
```
Or directly:
```bash
python dashboard.py
```

## 📖 Usage Guide

### Adding a Product
1. Select **1. Add Product**
2. Enter a unique integer ID (must be > 0)
3. Enter product name (max 20 characters)
4. Enter stock quantity
5. Enter unit price in Rs

### Recording a Sale
1. Select **3. Record a Sale**
2. Enter the product ID
3. Enter quantity to sell
4. System validates stock, deducts quantity, accumulates units sold, and prints total value

### Updating a Product
1. Select **4. Update Product**
2. Enter the product ID
3. Enter new name, quantity, and price

### Deleting a Product
1. Select **5. Delete Product**
2. Enter the product ID
3. Confirm with `1` (Yes) or cancel with `0` (No)

### Exporting Data
1. Select **6. Export Data to CSV**
2. File is written to `data\export.csv` automatically

## 💾 File Persistence

Data is saved to and loaded from `data\inventory_data.dat` as a raw binary file using Win32 API calls. The file layout is fixed at **364 bytes**:

| Field | Size | Description |
|-------|------|-------------|
| `itemCount` | 4 bytes | Number of active records |
| `itemIDs` | 40 bytes | 10 × DWORD product IDs |
| `itemQty` | 40 bytes | 10 × DWORD stock quantities |
| `itemPrice` | 40 bytes | 10 × DWORD unit prices |
| `itemSold` | 40 bytes | 10 × DWORD cumulative units sold |
| `itemNames` | 200 bytes | 10 × 20-byte name strings |
| **Total** | **364 bytes** | |

On first run (no file found), the system starts with empty arrays and prints:
```
[!] No previous data found. Starting fresh.
```

On exit, it overwrites the file and prints:
```
[OK] Inventory data saved safely to disk.
```

## 🧮 Memory Layout

With `MAX_ITEMS = 10`, the total in-memory footprint of all product data is:

```
4 arrays × 10 entries × 4 bytes  = 160 bytes  (IDs, Qty, Price, Sold)
1 name buffer × 10 × 20 bytes    = 200 bytes
itemCount                         =   4 bytes
──────────────────────────────────────────────
Total                             = 364 bytes
```

This is exactly the size of the binary file — `SaveData` and `LoadData` are a direct memory-to-disk dump and restore with no serialization overhead.
